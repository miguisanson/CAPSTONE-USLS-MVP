# Cross-cutting audit (v5.1-migui_clean, 2026-10-01)

Scope: frontend/backend contract, navigation, dashboard/queue/reports numbers, data model, seeds/walkthrough, robustness, documentation drift. Workflow-specific logic is covered by the other auditors.

How it was checked: `app.url_map` dumped with a throwaway script (137 rules, 135 under `/api`); every call in `frontend/src/api.js` matched against it by method and path; the Flask test client run against temporary SQLite databases only (fresh seed, a copy of the full seed, and databases rebuilt from old commits); the full test suite run once (80 tests, 78 pass, 2 fail -- the same two known failures: `test_workflow_clarification_can_be_returned_and_answered` and `test_workflow_demo_students_quick_login_and_central_reset`). No server was started. The real database was never opened.

Side effect to know about: `seed_database()` and the test suite write their generated PDFs into the real `uploads/` folder even when `DATABASE_URL` points at a temp file (see X07). `uploads/research_evidence/` and `uploads/student_requests/` are git-ignored, so `git status` is still clean.

Legend: VERIFIED = reproduced or unambiguous in code. SUSPECTED = plausible from code, not reproduced.

## 1. Headline numbers

- Frontend calls: 114 distinct `api.js` calls, 113 match a real route and method; the one "miss" is the dynamic `/student-portal/requests/${type}` (all 8 real types exist). No call to a missing route or wrong method.
- Routes with no caller in the UI: see C-section.
- Fresh seed gives 138 students, 12 faculty, 8 confirmed defenses, 7 open tasks (not the "~350" the README promises).

## 3. Checked and found consistent

- Every `api.js` call maps to an existing route and method. Payload keys for login, Dean decisions (`decision`/`note` for plans and workflow approvals, `decision`/`remarks` for onboarding and coursework), student enrollment (`course_ids`, `term_id`), assistant (`question`, `student_id`), merge (`target_id`, `source_id`) match the handlers.
- Role guards: frontend `ROLE_PATHS` and backend `ROLE_TRANSACTION_ACCESS` agree for Academic Coordinator and Research Coordinator; the 17-row access-control KPI passes. Admin passes every `require_api_login` gate but not `require_workflow_actor` (by design).
- No division by zero in the reports: `_percent` and the course-audit rates are guarded; empty student sets are handled. Dashboard `summary` inside `/api/reports` equals `/api/dashboard` `kpis`.
- No fake or random values in the analytics; the seeded demo numbers come from real rows.
- Migrations: databases built from 7 commits between 2026-06-26 and 2026-08-14 upgrade without any missing column; the Aug-6 backup also upgrades cleanly.
- File serving: uploaded files use uuid names, `secure_filename`, `send_from_directory`; research evidence, request attachments and policy files are checked against role/ownership; path-traversal probes on the SPA catch-all return 404 or the SPA page. Size checks exist (25 MB research evidence, 20 MB policy documents) but only after the whole upload is received (no `MAX_CONTENT_LENGTH`).
- Seeded demo students: all 19 `WORKFLOW_DEMO_STUDENTS` exist, are linked to their accounts, and the account list in walkthrough Section 4 matches the seed except the rows in M10.

## 4. Suggested order

1. H01 (student stuck after withdrawal), H02 (faculty logins on first start), H05 (merge data loss) - each is a small, testable fix.
2. H03 + H04 + M04 together (one owner constant, one task-closing helper, an explicit "closed" marker): they drive the wrong numbers on Dashboard, Work Queue, Decision Support and Analytics.
3. M01, M02, M03 (report caps, vocabulary, stale risk).
4. M08, M09, L01 (startup order, demo-only endpoints, JSON error handling).
5. Documentation (M10-M12) last, after the code settles.
